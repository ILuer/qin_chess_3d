# ADR-0001 采用零构建 ESM + importmap（无打包器）

- **状态**：已采纳（Accepted）
- **日期**：Phase 4 收尾补建（记录既有决策）
- **相关**：ADR-0002（本地 vendored Three.js）

## 背景（Context）

「秦风 · 3D 中国象棋」定位为**纯前端、即开即玩、易部署到任意静态托管 / 子路径**的 3D 小游戏。团队无专职构建 / 运维角色，且早期使用 CDN 加载三方库时有 DNS 解析与可用性历史问题（见 ADR-0002）。需要一种：

- 不需要安装 Node 工具链、不需要 `build` 步骤的方案；
- 源码即生产、便于审阅与人工走查；
- 不引入长期维护负担（升级/锁版本简单）的模块组织方式。

## 决策（Decision）

采用**原生 ES Module + importmap**，**不使用任何打包器**（Vite / Webpack / Rollup / esbuild 均不引入）。

- 入口即 `src/main.js`：`<script type="module" src="src/main.js">`；
- 三方依赖经 `importmap` 映射（见 ADR-0002 的本地 vendor 方案）；
- 项目内模块以相对路径 `import` 互相引用，保持扁平、`src/` 即根；
- 仅使用浏览器原生支持的语法（原生 JS，无 TS / JSX 等需编译特性）。

## 备选方案（Alternatives Considered）

1. **Vite + 打包**：开发体验好、有 tree-shaking，但引入构建步骤、依赖安装与升级维护成本，且产出与源码脱节、不便人工走查。
2. **CDN ESM（如 esm.sh / unpkg）**：零本地依赖，但复现性受网络/版本漂移影响，存在早期已踩过的 DNS/可用性风险（见 ADR-0002）。
3. **UMD / 全局 `<script>` 注入**：可行但丧失模块化、全局命名污染、无 `import` 静态分析。

## 后果（Consequences）

**正面**
- 零安装、零构建：`python -m http.server` 或任意静态服务器即可运行；
- 部署极简，且源码 = 生产代码，审阅与定位问题直接；
- 无构建产物，版本控制干净。

**负面 / 代价**
- 无 tree-shaking：依赖按全量加载（Three.js 整体进入，对单页小游戏可接受）；
- 需手动保证 `import` 路径与文件名正确（无打包器兜底）；
- 不支持需编译的语法（本项目据此选用原生 JS，是约束而非缺陷）；
- 模块数量增长后，浏览器需并行发起较多请求（HTTP/2 下影响有限）。

## 备注（Notes）

- `importmap` 一律使用**相对路径**写法，保证子路径部署（如 `/qin_chess_3D/`）同样成立；
- 该决策与 ADR-0002 共同构成"**零外部依赖**"目标：构建方式零工具、运行时零网络。
