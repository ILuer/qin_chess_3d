## 1. 听觉身份（Sonic Identity）

美术方向是「玄黑赤红 · 青铜甲胄 · 战鼓旌旗」。音频必须与之同构，因此整套声音的物理隐喻被锁定为三种材质：

| 材质 | 对应视觉 | 合成手段 | 用在哪 |
|------|---------|---------|--------|
| **青铜** | 甲胄、编钟、礼器 | **不谐和泛音列**正弦堆叠 | `select` 编钟、`check` 铜锣、`capture` 金属层、`lose` 丧锣 |
| **木 / 石** | 棋子、棋盘台面 | 白噪声爆发 + 带通滤波 + 极短包络 | `move`、`hover`、各类瞬态 |
| **皮革 / 气** | 战鼓、埙、号角 | 低频正弦下滑 / 锯齿波 + 低通「吹口」包络 | `check` 战鼓、`start` 号角、`win`/`lose` 收尾鼓 |

### 1.1 为什么坚持「不谐和泛音」

真实青铜钟体的分音比不是 1:2:3（整数谐波），而是接近 `[1, 1.19, 2.0, 2.76, 3.61, 5.42]`。
**这组比值才是"金属味"的来源**。若用整数谐波堆叠，听感会立刻退化成廉价的 FM 电子音。
`bronzeBody()` 就是这条原则的唯一实现，编钟 / 铜锣 / 丧锣共用它，只改基频、衰减倍率与分音表。

编钟额外还原了 **「一钟双音」**：合瓦形钟体正鼓与侧鼓相差约小三度，
所以 `select` 的分音表里同时存在 `1.0`（正鼓音）与 `1.19`（侧鼓音）两个基音。

### 1.2 调式：五声音阶（宫商角徵羽）

所有旋律性素材只用五声音阶，避免半音带来的近现代听感。

```
宫 C   商 D   角 E   徵 G   羽 A
```

唯一的例外是 `lose`：刻意使用 **A 小调下行（A→G→F→E）**，落在五声语汇之外的 F 音上，
制造「秩序被破坏」的失序感。这是一次**有意的规则违反**，不是疏漏。

### 1.3 空间：程序化「石殿混响」

`ConvolverNode` + 代码生成的 1.5s 立体声脉冲响应（`buildImpulseResponse()`）。
IR 不是简单的「噪声 × 指数衰减」，还做了三件事：

- **逐样本一阶低通**（左右系数 0.38 / 0.41）→ 削掉数字混响特有的白亮尾巴，得到石材/木构的暗色残响；
- **左右声道独立随机序列 + 不同衰减系数**（5.2 / 4.9）→ 天然去相关，产生立体声宽度，无需额外 widener；
- **12ms 预延迟淡入窗** → 直达声与混响分离，打击感不被残响糊住。

这条混响是整套音效「不廉价」的关键，也是唯一的全局共享空间。

## 2. 信号链总览

```
                                      ┌──────────────► dryBus ─────────┐
 [源: Osc / BufferSource]             │                                │
        │                             │                                ▼
        ├─► [Filter] ─► [envGain] ─► voiceBus ─► (StereoPanner)   masterGain ─► DynamicsCompressor ─► destination
        │                                   │                          ▲            (thr -12dB, knee 22,
        └─► ...（多层叠加）                  └─► sendGain(wet) ─► Convolver ─► wetBus     ratio 8:1, atk 3ms, rel 250ms)
                                                                 (1.5s 程序化 IR)
```

- **每次 `play()` 独立创建一条 voiceBus**，播放结束后由 `scheduleRelease()` 定时 `disconnect()`，不留节点泄漏。
- **干声恒定为 1.0，混响用 send 量控制**（标准 send 架构），因此调 wet 不会削弱瞬态清晰度。
- **压缩器只当安全网**：正常单发不触发，只在 `check` + `move` + `hover` 同时叠加时兜底防爆。

## 3. 逐音效合成信号链

### 3.1 `select` —— 选中棋子｜编钟单击

```
mallet:  Noise ─► BP 4.2kHz Q1.6 ─► AD(1ms/12ms) ────┐
bell:    6 × Sine(880 × [1.0, 1.19, 2.0, 2.76,      ├─► voiceBus ─► dry
                        3.61, 5.42], ±0.3% 失谐)     │            └─► wet 0.16
              每分音独立 AD 包络，高次分音衰减更快 ────┘
```
- 基频 880Hz，总时长约 0.85s（主音）／0.11s（最高分音）。
- 每个分音额外 ±0.3% 失谐 + ±6 音分 detune，防止相位锁死产生的电子感。
- **一句话音色**：一记清亮的小编钟，带小三度侧鼓音的双音摇曳。

### 3.2 `hover` —— 悬停己方棋子｜近乎潜意识的高频点

```
Noise ─► BP 5.2kHz Q2.2 ─► AD(1ms/18ms) ─┐
Sine 2600Hz ─► AD(2ms/30ms) ─────────────┴─► voiceBus ─► dry / wet 0.05
```
- 峰值 **-19.2 dB**，总时长 <30ms。全项目触发最频繁的声音，电平必须压到几乎察觉不到。
- **一句话音色**：指尖擦过青铜的一粒微光。

### 3.3 `move` —— 落子（未吃子）｜木石相击

```
body:  Noise ─► BP 1200Hz→760Hz Q1.1 ─► AD(1ms/60ms) ─┐
snap:  Noise ─► BP 3.4kHz Q1.8 ─► AD(1ms/16ms) ───────┼─► voiceBus ─► dry / wet 0.10
thud:  Sine 150Hz→104Hz ─► AD(3ms/110ms) ─────────────┘
```
- 带通中心频率在 60ms 内从 1200Hz 下滑到 760Hz —— 撞击后腔体共振下移，这是「木头」而非「塑料」的关键。
- 低频 150Hz「咚」层给出重量，让落子坐在混音底部。
- **一句话音色**：一枚青铜棋子磕在石案上的干脆一声「啪」。

### 3.4 `capture` —— 吃子｜比 move 明显更重

```
① sub:    Sine 88Hz→42Hz ─► AD(4ms/260ms) ────────────┐
② burst:  Noise ─► LP 6kHz→700Hz Q0.9 ─► AD(2ms/190ms)├─► voiceBus ─► dry
③ metal:  3 × Square(2100/3170/4430Hz) ─► BP Q6       │            └─► wet 0.34（长尾）
             ─► AD(2ms/200~120ms), 逐层错开 4ms ───────┤
④ onset:  Noise ─► BP 2.6kHz Q1.2 ─► AD(1ms/22ms) ────┘
```
- 与 `move` 的听感差距靠三件事拉开：**低 8 度的冲击基频**、**+3.9 dB 电平**、**3.4 倍的混响送量**。
- 方波经 Q=6 带通后只保留窄带金属共振，避免方波原始齿感的刺耳。
- **一句话音色**：兵器劈中甲胄，低频闷响裹着一层金属碎裂的余音。

### 3.5 `check` —— 将军｜战鼓 + 铜锣

```
drum×2:  Sine 62→40Hz  AD(4ms/320ms) + 木质瞬态 320Hz/1.8kHz     ┐
         Sine 58→38Hz（+190ms 二连击，轻）                        │
gong:    7 × Sine(248 × [1.0, 1.42, 1.88, 2.41, 3.17,           ├─► voiceBus ─► dry
                        4.63, 6.21])                             │            └─► wet 0.60
         衰减倍率 2.6（最长 2.47s）                                │
         LFO 4.6Hz ─► ±9 音分 ─► 所有分音 detune（锣面震颤）       │
mallet:  Noise ─► BP 1.5kHz Q0.8 ─► AD(1ms/60ms)（+30ms）────────┘
```
- **鼓先落，锣晚 30ms 跟上**。这个微小时间差比同时触发更像真实军阵的击鼓鸣金。
- 分音比 `1.42 / 1.88 / 2.41` 比编钟更不谐和，是铜锣「哐」的核心。
- 全局最高电平 **-1.4 dB** + 最长衰减，紧张感来自「压过一切其他声音」。
- **一句话音色**：两记战鼓砸下，一面铜锣在殿中震颤不散。

### 3.6 `illegal` —— 非法走法｜否定但不伤耳

```
note1: Square 200→168Hz ─► AD(6ms/75ms) ─┐
note2: Square 150→126Hz ─► AD(6ms/75ms) ─┼─► LP 520Hz Q0.9 ─► voiceBus ─► dry / wet 0.06
       （+90ms）                          │
thud:  Sine 110→84Hz ─► AD(5ms/150ms) ───┘（直连，不过低通）
```
- **设计约束优先于表现力**：玩家一局可能听到几十次。因此 520Hz 低通砍掉全部刺耳成分、
  峰值仅 -10.5 dB、总时长 165ms、混响送量几乎为零（不留残响污染下一次操作）。
- 两个**快速下行**音（音高下降 = 否定，这是跨文化的心理声学共识）。
- **一句话音色**：两声闷在喉咙里的「咄—咄」，明确拒绝但不惹人烦。

### 3.7 `undo` —— 悔棋｜倒放感上滑

```
main:  Sine 220→660Hz     ┐
harm:  Triangle 330→990Hz ├─► 反向包络: swell 到 78% 时长, 然后 50ms 骤收 ─► voiceBus
hiss:  Noise ─► BP 800→3600Hz Q2.4 ┘                                      └─► wet 0.30
```
- **「倒放感」的本质是反向包络**：缓慢起音（0.33s swell）+ 骤然收尾，
  与一切自然打击声的「瞬起缓落」相反，大脑会把它解读为「时间倒流」。
- 三层同步上扫，嘶声层模拟磁带倒转。总时长 0.47s。
- **一句话音色**：时间被轻轻倒抽回去的一道气声上滑。

### 3.8 `start` —— 开局｜秦风号角动机

```
t=0.00  warDrum 70→44Hz
t=0.06  hornNote 徵 G3 196.0Hz  (0.26s)
t=0.32  hornNote 宫 C4 261.6Hz  (0.24s)
t=0.55  hornNote 商 D4 293.7Hz  (0.20s)
t=0.73  hornNote 徵 G4 392.0Hz  (0.46s, 拉长收尾)  +  warDrum 66→42Hz
                                          总时长 ≈ 1.21s, wet 0.45
```
`hornNote()` 单音内部：
```
2 × Sawtooth(f, f×1.004, ∓7音分) ─┐
                                  ├─► LP 420Hz→f×5.5→f×2.2 (Q3.2) ─► ASR ─┐
Sine f/2（胸腔共鸣） ─► ASR ───────────────────────────────────────────────┼─► bus
Noise ─► BP f×3 Q1.1 ─► ASR ×0.09（吹奏气声）────────────────────────────┘
```
- 低通截止频率在起音时上扫 —— 这是模拟**气流建立过程**，没有它锯齿波只会像合成器 lead。
- 双锯齿微失谐（0.4%）产生自然拍频；气声层让它像「人吹的」而非「机器发的」。
- **一句话音色**：升帐点兵，一记鼓落定，四声上行号角撞在殿墙上。

### 3.9 `win` —— 胜利｜上行五声琶音 + 凯旋鼓

```
t=0.000 ~ 0.575  chimeNote × 6：宫C4 商D4 角E4 徵G4 羽A4 宫C5（间隔 115ms，逐音渐强渐长）
t=0.62           bronzeBody 大编钟 @ 宫C5，衰减倍率 1.6
t=0.86 / 1.04 / 1.18   warDrum ×3（加速三连击，末击最重）
                                          总时长 ≈ 1.58s, wet 0.42
```
`chimeNote()` = Triangle(f) + Sine(f×2.74)×0.18 + Sine(f/2)×0.30 —— 明亮但仍带一点不谐和分音，避免过于「玩具」。
- **一句话音色**：五声琶音一路攀升撞上大钟，三记战鼓收官。

### 3.10 `lose` —— 失败｜下行小调 + 丧锣

```
t=0.00  hornNote A3 220.0Hz (0.30s)
t=0.26  hornNote G3 196.0Hz (0.30s)
t=0.52  hornNote F3 174.6Hz (0.32s)   ← F 音落在五声之外，制造失序感
t=0.80  hornNote E3 164.8Hz (0.55s)
t=0.78  bronzeBody 丧锣 @132Hz，衰减倍率 3.0（最长 2.85s），LFO 2.2Hz 缓慢震颤
t=0.78  warDrum 54→33Hz（沉闷收尾）
                                          总时长 ≈ 3.6s（含锣尾）, wet 0.55（全曲最湿）
```
- 号角频率整体降八度处理（`× 0.5`），音色比 `start` 暗得多。
- 铜锣震颤 LFO 从 4.6Hz（check 的紧张）降到 2.2Hz（迟缓、垂死）。
- **一句话音色**：四声下行的暗号角，坠进一面久久不散的低沉丧锣。

## 4. 混音电平表

峰值增益为进入 voiceBus 前的线性值，dBFS 为相对满刻度（`20·log₁₀`）。
主输出还会再乘 `settings.volume × 0.9(HEADROOM)`，默认 0.8 → 实际再 -1.9 dB。

| 音效 | 峰值增益 | dBFS | 混响送量 | 典型时长 | 分层数 | 设计意图 |
|------|---------|------|---------|---------|-------|---------|
| `check` | 0.85 | **-1.4** | 0.60 | 2.5 s | 3 层 + 7 分音 | 全曲最响，必须压过一切 |
| `capture` | 0.78 | -2.2 | 0.34 | 0.35 s | 4 层 | 比 move 高 3.9 dB，重量差距一耳可辨 |
| `move` | 0.50 | -6.0 | 0.10 | 0.17 s | 3 层 | 核心交互基准电平 |
| `win` | 0.50 | -6.0 | 0.42 | 1.58 s | 6 音 + 钟 + 3 鼓 | 明亮但不过载 |
| `lose` | 0.46 | -6.7 | 0.55 | 3.6 s | 4 音 + 锣 + 鼓 | 最湿，空间感最大 |
| `start` | 0.42 | -7.5 | 0.45 | 1.21 s | 4 音 + 2 鼓 | 仪式感 |
| `select` | 0.34 | -9.4 | 0.16 | 0.85 s | 6 分音 + 瞬态 | 高频集中，低电平也清晰 |
| `illegal` | 0.30 | -10.5 | 0.06 | 0.17 s | 3 层 | 频繁出现，必须克制 |
| `undo` | 0.26 | -11.7 | 0.30 | 0.47 s | 3 层 | 轻柔，不打断思路 |
| `hover` | 0.11 | **-19.2** | 0.05 | 0.03 s | 2 层 | 触发最频繁，近乎潜意识 |
| `ambient` | 0.05 | -26.0 | 0.50 | 循环 | 风 + 远鼓 | 底噪，绝不抢戏 |

**动态范围：`hover` 到 `check` 相差 17.8 dB** —— 这个跨度保证了戏剧性事件真的「大」，
而高频操作真的「小」，不会所有声音挤在同一响度而听觉疲劳。

### 4.1 频段分工（避免互相遮蔽）

| 频段 | 占用者 |
|------|--------|
| 33–150 Hz | 战鼓、capture 低频冲击、move 的「咚」、丧锣基频 |
| 150–600 Hz | 号角/埙旋律、illegal（全部低通到 520Hz） |
| 600–2 kHz | move/capture 木石主体、铜锣中分音 |
| 2–5 kHz | 编钟主分音、金属层、各类瞬态 |
| 5 kHz+ | hover、mallet 瞬态 |

`illegal` 被强制关在 520Hz 以下，就是为了让它**永远不与 move/capture 的中高频瞬态打架** ——
即便玩家在连续试错时反复触发，也不会形成刺耳的高频堆积。

## 5. 实现要点

### 5.1 自动播放策略（必读）
`AudioContext` **只在 `SFX.init()` 里创建**，且必须由 engineering-lead 在**首次用户手势的同步调用栈**中调用：

```js
// engineering-lead 侧（src/main.js）
window.addEventListener('pointerdown', () => SFX.init(), { once: true });
// 或者绑在「开始对局」按钮上，随后立刻 SFX.play('start')
```
- 未 `init()` 时所有 `play()` **静默返回 `false`**，不抛错、不打日志、不影响游戏逻辑。
- `init()` 可重复调用；切换标签页后 context 被 suspend 时，再次 `init()` 或 `play()` 会自动尝试 `resume()`。

### 5.2 防爆音
- 所有增益包络一律 `setValueAtTime` → `exponentialRampToValueAtTime` / `linearRampToValueAtTime`，**没有任何一处直接给 `.value` 赋跳变值**。
- `exponentialRamp` 的目标永远不为 0，统一使用地板值 `FLOOR = 0.0001`。
- `setVolume()` 也走 50ms `linearRamp`，拖动音量滑杆不会咔哒。
- 末级 `DynamicsCompressor`（-12 dB / 22 knee / 8:1 / 3ms / 250ms）作为安全网。

### 5.3 节流
同名音效 30ms 内重复触发直接丢弃（`THROTTLE_MS`）。
连点棋子时 `select`/`hover` 不会叠成噪声墙。**注意：被节流的调用返回 `false`**，
engineering-lead 不应依赖 `play()` 返回值来驱动任何游戏逻辑。

### 5.4 微随机化（Juice 的一部分）
每次 `play()`：
- 频率 **±3%**（`rand(0.97, 1.03)`）
- 音量 **±8%**（`rand(0.92, 1.08)`）
- 噪声源从共享缓冲的**随机偏移**处读取
- 每个青铜分音额外 ±0.3% 失谐 + ±6 音分 detune

结果：连下十步棋，十次 `move` 没有一次完全相同。**机械重复感是廉价感的最大来源**。

### 5.5 声像定位（给 engineering-lead 的接口）
`opts.pan` 范围 -1..1，用 `StereoPannerNode`。建议按棋子纵线映射：

```js
// file: 0..8  →  pan: -0.6 .. +0.6（不要用满 ±1，会脱离画面）
const pan = (file - 4) / 4 * 0.6;
SFX.play('move', { pan });
SFX.play('capture', { pan });
```
`check` / `start` / `win` / `lose` 属于全局事件，**建议 pan 保持 0**（居中）。
不支持 `StereoPannerNode` 的老浏览器自动降级为单声道，不报错。

### 5.6 状态持久化
`localStorage` 键 `qin-chess-audio`，存 `{ enabled, volume, ambient }`。
模块加载时即读取（`init()` 之前），所以 UI 可以在音频还没启动时就正确渲染静音按钮与音量滑杆状态。
隐私模式 / 存储被禁用时静默降级为内存态。

### 5.7 性能预算

| 项 | 实测 |
|----|------|
| 常驻内存 | 白噪声缓冲 384 KB（2s 单声道 @48k）+ 混响 IR 576 KB（1.5s 立体声）≈ **0.94 MB** |
| 单次发声节点数 | hover 8｜move 11｜select 18｜capture 20｜check 38｜start 59｜lose 63｜win 73 |
| 最坏并发 | hover + move + check 同时 ≈ **57 节点**（+ ambient 常驻 ~10） |
| 节点回收 | 每条 voiceBus 在预计生命周期 +350ms 后 `disconnect()`，长会话无泄漏 |
| CPU | 单条 ConvolverNode 全局共享（非每音效一条），是本方案 CPU 开销的主要项，1080p/60fps 下无可测帧率影响 |

`win`（73 节点）是全场最重的一次发声，但它一局只出现一次且在游戏结束时，不与渲染高峰重叠。

### 5.8 环境氛围层（契约外附加）
```
Noise(playbackRate 0.32, loop) ─► LP 300Hz Q1.6 ─► gain 0.55 ─┐
   LFO 0.055Hz ×130 ─► LP.frequency（缓慢推拉截止频率）        ├─► out(0.05) ─► dry
   LFO 0.083Hz ×0.28 ─► gain.gain（呼吸感）                    │            └─► wet 0.50
远处战鼓：每 6~14s 随机一记 warDrum(52~64Hz, 电平 0.16, 高湿) ──┘
```
- 开关：`SFX.setAmbient(true/false)`，1.5s 淡入 / 0.8s 淡出，无咔哒。
- 状态持久化，`init()` 时若上次为开则自动恢复。
- **默认关闭** —— 需要 UI 提供一个独立开关（不要和主静音混在一起）。

## 6. 导出 API 速查

```js
import { SFX } from './audio/sfx.js';

// —— 契约内（docs/CONTRACT.md §3）——
SFX.init();                                      // -> boolean，首次用户手势内调用
SFX.play(name, { volume, pitch, pan });          // -> boolean，是否真的发声
SFX.setEnabled(bool);                            // -> boolean
SFX.setVolume(0..1);                             // -> number
SFX.isEnabled();                                 // -> boolean

// —— 附加（可选，不调用不影响任何行为）——
SFX.getVolume();                                 // -> number
SFX.isReady();                                   // -> boolean，AudioContext 是否已建立
SFX.setAmbient(bool);                            // -> boolean，环境氛围层
SFX.isAmbient();                                 // -> boolean
SFX.stopAll();                                   // 应急：20ms 内淡至静音，240ms 恢复
```

`name` 取值：`'select' | 'hover' | 'move' | 'capture' | 'check' | 'illegal' | 'undo' | 'start' | 'win' | 'lose'`

`opts` 全部可选：`volume` 相对倍率（0..2，默认 1）｜`pitch` 音高倍率（默认 1，0.5=低八度）｜`pan` 声像（-1..1，默认 0）。

## 7. 已知限制

1. **`pitch` 是全局频率倍率**，会同时改变旋律音与打击瞬态。对 `start`/`win`/`lose` 这类旋律动机，
   建议保持 `pitch = 1`，否则调式关系虽保持但音区会整体偏移。
2. **混响是单一全局 IR**，无法按事件切换空间（例如"殿内 / 野外"）。
   目前所有声音共享同一个石殿空间，这是有意的一致性选择。
3. **`check` 的锣尾约 2.5s**，若在 2.5s 内连续将军两次，第二次会与前一次的尾巴叠加。
   节流窗口只有 30ms，管不到这种情况；实测叠加后由压缩器兜住，不爆音，但会略显浑浊。
4. **Safari 的 `DynamicsCompressor` 曲线与 Chrome 略有差异**，Safari 上整体感知响度约低 1–2 dB，不影响可用性。
5. **没有 VO（配音）**。当前版本无任何人声素材，全部靠器乐语汇表达状态。

## 8. 未来扩展建议

| 优先级 | 提案 | 说明 |
|-------|------|------|
| P1 | **走子记谱的音高编码** | 按棋子类型给 `move` 分配不同基频（车低、马中、兵高），让老玩家闭眼也能听出走的是什么子。改动量小，Windex 价值高。 |
| P1 | **将军的紧迫度分级** | `play('check', { pitch: 1.0 / 1.08 / 1.15 })` 对应将军 / 双将 / 将死前一步，用音高递进传递危险等级。**接口已支持，无需改代码**。 |
| P2 | **动态音乐层** | 按局面紧张度（双方剩余子力差 + 是否被将）在 2–3 个低强度循环层之间交叉淡入淡出。需新增 `SFX.setTension(0..1)`。 |
| P2 | **思考中的心跳层** | 轮到玩家且超过 20s 未落子时，淡入一个 60 BPM 的极轻低频脉冲，超时前 5s 加速。 |
| P3 | **秦式打击乐胜利 Cue 扩写** | 把 `win` 从 1.6s 扩到 4s 的完整凯旋段落（编钟 + 建鼓 + 埙），需要与结算 UI 的动画时长对齐。 |
| P3 | **VO 方向** | 若未来加入解说，声线定位建议：低沉、缓慢、略带沙哑的中年男声（史官口吻），只念招法与关键状态（"将军"、"和棋"），不做情绪化解说。需与 design-strategist 确认是否符合体验基调。 |
| P3 | **可访问性：音效字幕** | 为听障玩家提供「声音事件字幕」开关，把每次 `play()` 的语义（落子/吃子/将军）以短提示条呈现。需 engineering-lead 在 UI 层配合。 |
