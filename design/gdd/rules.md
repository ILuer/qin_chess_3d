# GDD · 规则系统 (rules)

## 1. 概述
规则引擎为纯逻辑层（不依赖 Three.js），是棋盘状态、合法性、胜负判定的唯一真相源；被 UI、AI（含 Worker）、动画、音频共同消费。

## 2. 目标
精确实现中国象棋标准规则，输出可被渲染 / AI 直接消费的可序列化状态；保证零状态分叉。

## 3. 核心循环
`genPseudoMoves(type)` → `makeMove→isAttacked/isFacingKings 过滤` → `generateLegalMoves` → `getGameStatus` → 记谱 / 事件。

## 4. 机制
- 棋盘 9 列(FILES) × 10 行(RANKS)，`GRID=1.0`；九宫 file 3..5，黑方 rank 0..2、红方 rank 7..9。
- 七子走法：将(九宫一步 / 白脸将非法)、士(九宫斜)、象(田字不过河 + 塞象眼)、马(日字 + 蹩马腿)、车(直线)、炮(隔一子吃)、兵(向前 / 过河横走不后退)。
- 将军 = 王被攻击；将死 = 被将且无合法解；**困毙 = 无合法走法即判负**（非和棋）。
- 白脸将（两王同列无子间隔）为非法局面。

## 5. 数值
棋子价值：将 100000 / 车 900 / 炮 450 / 马 400 / 象 200 / 士 200 / 兵 100；过河兵 200。
和棋阈值：`DRAW_HALFMOVE_HINT=120`，`DRAW_HALFMOVE_LIMIT=240`（半回合数）。

## 6. 边界与异常
- 落子致己方被将 / 白脸将 → `explainIllegal` 返回 UI toast 原因。
- 阻挡提示：蹩马腿 / 塞象眼 / 不可过河 → 灰叉（`getBlockers`）。
- 光将（仅双王）→ 和棋；半回合 ≥ LIMIT → 和棋；可协议和棋。
- `undo(steps)`：人机模式传 2 退两步以回到玩家回合。

## 7. 跨系统依赖
- 依赖：`constants`（坐标 / ID / 价值）。
- 被依赖：AI（搜索复用 rules）、gameState（历史 / 记谱 / 状态）、UI（合法性提示）、动画 / 音频（事件派生）。

## 8. 开放问题
- 长将（连续将军）判负规则未实现，目前仅困毙判负。
- 重复局面 / 三次和棋未实现，长捉对僵局无兜底。
